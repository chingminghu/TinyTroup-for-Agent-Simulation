# Switching API Providers

TinyTroupe selects its model provider through the `[OpenAI]` section of a
`config.ini` file. The supported `API_TYPE` values are `openai`, `azure`,
`gemini`, `openrouter`, and `ollama`.

Create `config.ini` in the directory from which you start Python. TinyTroupe
loads its bundled defaults first, then overrides them with values from this
file. Set credentials as environment variables rather than putting secrets in
`config.ini`.

After changing providers, restart the Python process or notebook kernel because
TinyTroupe loads and caches configuration during import.

## Configuration overview

| Provider | `API_TYPE` | Credential | Model-name format |
| --- | --- | --- | --- |
| OpenAI | `openai` | `OPENAI_API_KEY` | `gpt-...` |
| Azure OpenAI | `azure` | `AZURE_OPENAI_KEY` and `AZURE_OPENAI_ENDPOINT` | Azure deployment name |
| Gemini API | `gemini` | `GEMINI_API_KEY` | `gemini-...` |
| OpenRouter | `openrouter` | `OPENROUTER_API_KEY` | `provider/model` |
| Ollama | `ollama` | None for a default local server | Ollama model tag |

`MODEL` is used for normal agent responses, `REASONING_MODEL` for operations
that request a reasoning model, and `EMBEDDING_MODEL` for semantic memory and
retrieval. All configured model names must be available from the selected
provider.

## OpenAI

Set the API key:

```bash
export OPENAI_API_KEY="your-key"
```

Create or update `config.ini`:

```ini
[OpenAI]
API_TYPE=openai
MODEL=gpt-5-mini
REASONING_MODEL=o3-mini
EMBEDDING_MODEL=text-embedding-3-small
```

## Azure OpenAI Service

Use the resource endpoint and API key:

```bash
export AZURE_OPENAI_ENDPOINT="https://your-resource.openai.azure.com/"
export AZURE_OPENAI_KEY="your-key"
```

If no `AZURE_OPENAI_KEY` is set, TinyTroupe attempts Microsoft Entra ID
authentication through `DefaultAzureCredential`.

In Azure, model values are deployment names, not necessarily the underlying
model IDs:

```ini
[OpenAI]
API_TYPE=azure
AZURE_API_VERSION=2024-12-01-preview
MODEL=your-chat-deployment
REASONING_MODEL=your-reasoning-deployment
EMBEDDING_MODEL=your-embedding-deployment
AZURE_EMBEDDING_MODEL_API_VERSION=2023-05-15
```

Use API versions supported by your Azure resource and deployments.

## Gemini API

Set the Gemini API key:

```bash
export GEMINI_API_KEY="your-key"
```

Use Gemini's native model IDs without an OpenRouter-style `google/` prefix:

```ini
[OpenAI]
API_TYPE=gemini
MODEL=your-gemini-chat-model
REASONING_MODEL=your-gemini-reasoning-model
EMBEDDING_MODEL=gemini-embedding-001
```

TinyTroupe accesses Gemini through Google's fixed OpenAI-compatible endpoint:

```text
https://generativelanguage.googleapis.com/v1beta/openai/
```

`gemini-embedding-2` can also be used where supported. Its vector space is not
compatible with `gemini-embedding-001`, so rebuild existing vector indexes when
switching between them.

## OpenRouter

Set the OpenRouter API key:

```bash
export OPENROUTER_API_KEY="your-key"
```

OpenRouter model IDs include the provider prefix:

```ini
[OpenAI]
API_TYPE=openrouter
MODEL=provider/your-chat-model
REASONING_MODEL=provider/your-reasoning-model
EMBEDDING_MODEL=openai/text-embedding-3-small
```

For example, a Gemini embedding model routed through OpenRouter is named
`google/gemini-embedding-001`, while direct Gemini API usage names the same
model `gemini-embedding-001`.

TinyTroupe uses OpenRouter's fixed endpoint:

```text
https://openrouter.ai/api/v1
```

Choose embedding models from OpenRouter's embedding catalog. A chat model
cannot be used as `EMBEDDING_MODEL` unless it explicitly supports the
embeddings endpoint.

## Ollama

Ollama support is experimental. Start a local server and pull a model:

```bash
ollama pull gemma3:1b
ollama serve
```

Configure the local OpenAI-compatible endpoint explicitly:

```ini
[OpenAI]
API_TYPE=ollama
BASE_URL=http://localhost:11434/v1
MODEL=gemma3:1b
```

The current Ollama client switches chat generation only. TinyTroupe's
LlamaIndex embedding setup does not route embeddings to Ollama, so features
that require embeddings still need a separately supported embedding setup.
See the [Ollama guide](./ollama.md) for the current limitations.

## Switching checklist

1. Change `API_TYPE` in the working directory's `config.ini`.
2. Set the selected provider's credential environment variables.
3. Replace `MODEL`, `REASONING_MODEL`, and `EMBEDDING_MODEL` with names valid
   for that provider.
4. Restart the Python process or notebook kernel.
5. Rebuild stored vector indexes if the embedding model changed.

Do not reuse stored vectors generated by different embedding models, even when
the models return vectors with the same number of dimensions.
